# Implementation Plan: Prompt Templates and Structured Output

**Branch**: `005-prompt-templates-structured-output` | **Date**: 2026-10-15 | **Spec**: [spec.md](spec.md)

## Summary

Move server-owned system prompts into classpath resources selected by request identifier, render template variables with `StTemplateRenderer` using `<` and `>` delimiters, and add typed structured extraction with independently selectable Spring AI validation and Ollama provider-schema modes.

The requested target model is `llama3.2:3b`, but the repository's current `application.properties` still selects `llama3`. This feature uses the configured Ollama model and does not migrate that setting. The loopback behavior harness uses the requested model name only in synthetic API payloads; it is not a real model inference.

## Verified Spring AI 2.0.0 classpath

Inspected the locally resolved 2.0.0 JAR contents and method signatures before feature code changes:

- `spring-ai-template-st-2.0.0.jar`: `org/springframework/ai/template/st/StTemplateRenderer.class` (`org.springframework.ai.template.st.StTemplateRenderer`).
- `spring-ai-model-2.0.0.jar`: `org/springframework/ai/converter/BeanOutputConverter.class` (`org.springframework.ai.converter.BeanOutputConverter`).
- `spring-ai-client-chat-2.0.0.jar`: `org/springframework/ai/chat/client/ChatClient$EntityParamSpec.class` (`org.springframework.ai.chat.client.ChatClient.EntityParamSpec`).

`javap` on the resolved JARs confirmed `ChatClient.CallResponseSpec.entity(Class<T>, Consumer<ChatClient.EntityParamSpec>)`, the `validateSchema()` and `useProviderStructuredOutput()` switches, `PromptSystemSpec.text(Resource)`/`params(Map)`, and `ChatClient.Builder.defaultSystem(Resource)`/`defaultAdvisors(...)`. `StTemplateRenderer.Builder` exposes `startDelimiterToken(char)` and `endDelimiterToken(char)`.

Package verification is from the dependency classpath resolved for this backend, not imports guessed from older Spring AI versions. The Jackson annotations used for schema-required fields remain under `com.fasterxml.jackson.annotation` (Jackson 3 relocated databind/core to `tools.jackson`, not annotations).

## Decisions

- A caller supplies a template ID and values for that template's named variables, never the system prompt text. Registry lookup limits available instructions; each entry owns its classpath resource and variable allowlist. This avoids client replacement of privileged system instructions and makes prompt changes auditable.
- Configure one `StTemplateRenderer` on the shared `ChatClient.Builder` with `startDelimiterToken('<')` and `endDelimiterToken('>')`. One renderer keeps variable syntax consistent across the registry; the extractor's JSON braces stay literal. Restrict templates from introducing unsupported delimiter conventions.
- Templates are classpath `Resource`s. Use the request's registered resource through the system-prompt spec while preserving the shared client configuration.
- Structured modes: `FRAMEWORK_VALIDATION` enables `validateSchema()`; `PROVIDER_SCHEMA` enables `useProviderStructuredOutput()`; `BOTH` enables both only for a separate combined experiment. Compare the first two modes with otherwise identical inputs. The framework validator can repair and retry; provider format constrains generation but does not itself run framework schema validation or promise a retry. The native Ollama format is the JSON schema generated by `BeanOutputConverter`.
- Define a small `ExtractedItem` domain type with all fields required via `com.fasterxml.jackson.annotation.JsonProperty(required = true)` and descriptions as needed. Keep the Jackson annotation package as `com.fasterxml.jackson.annotation`, despite Jackson 3's other package relocations.
- Template token overhead is model/input dependent. For each registered template, measure prompt token delta against no system template on the same prompt/model via response usage. In local Ollama the direct monetary charge is zero; the cost is additional prompt-evaluation compute and latency on every turn. Do not claim a fixed token count without measurement.
- Preserve the existing 003/004 fields and behavior; do not edit their specifications or unrelated implementation paths.

## defaultSystem, request templates, and future memory advisor (006)

`defaultSystem(Resource)` establishes a resource-backed default on the shared ChatClient builder. A request-selected system template overrides that default for that call; it does not append a second system prompt implicitly. If 006 adds a memory advisor, configure `defaultAdvisors(...)` on the same builder alongside `defaultSystem(...)`. The prompt's selected system resource is set before advisor execution; the advisor then augments the request with memory context. The plan must retain the chosen order explicitly: system instructions first, memory advisor composition afterward. Memory remains out of scope here.

## Implementation Shape

1. Register classpath resources and per-template variable allowlists.
2. Validate request IDs/modes/variables before the model call.
3. Set a shared renderer with angle-bracket delimiters.
4. Define the required-field `ExtractedItem` entity and Jackson annotations from `com.fasterxml.jackson.annotation`.
5. Apply sampling options from feature 004 to the same request before `.entity()`; compare both structured modes using identical prompt/template/model.
6. Add response fields additively, with unstructured chat remaining the default.
7. Measure per-template token deltas using prompt usage and record the result in research/quickstart after live verification.
